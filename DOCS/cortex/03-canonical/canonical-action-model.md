# Canonical Action Model

## Purpose
Represent actionable commitments or execution steps extracted from events/discussions.

## Lifecycle
- extracted from explicit action markers or structured commands,
- linked to owners/artifacts when explicitly evidenced,
- status may evolve through later observed events.

## Ontology Semantics
- action is operational intent/execution unit.
- action is distinct from decision and artifact.

## Provenance
- action must reference source evidence and extraction path.

## Temporal
- supports created/updated/completed/superseded timeline.

## Ambiguity/Confidence
- uncertain owner/target fields remain unresolved with confidence tags.
