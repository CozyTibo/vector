# Canonicalization Layer Overview

## Why this phase exists

Phase 03 isolates **deterministic structural projection** from Phase 02 raw organizational memory into **canonical organizational primitives** so higher phases can build cognition on stable, replayable structures—not ad hoc joins over raw JSON.

## Implementation-grade program (not a single umbrella step)

Phase 03 executes as **18 explicit stages** (ontology → mapping system → ambiguity → replay/provenance/temporal → query → failure/remediation → verification → control plane → stabilization → certification). See:

- **`implementation-plan.md`** — sequencing, dependency graph, runtime responsibility matrix,
- **`MASTER_TRACKER.md`** — Phase 03 Steps **1–18**.

This decomposition is intentional: **each stage owns one primary runtime concern** to prevent implementation drift.

## Responsibilities (normative summary)

- Deterministic mapping from raw evidence to canonical entities, events, relationships, references, and timelines.
- **Mapping system** governance: bundle registry, pins, compatibility, logical keys, transform lineage.
- Preserving **ambiguity** and **confidence semantics** without silent elimination.
- Maintaining **full provenance traceability** and **replay/rebuild** equivalence classes (C0–C5).
- Operating **verification**, **remediation**, and **operator control plane** as separable runtimes.

**Authoritative doctrine index:** `phase-03-normative-index.md`.

## Non-responsibilities

- Semantic interpretation, prioritization, managerial summaries, predictions, graph cognition, AI retrieval — see `phase-03-anti-goals-doctrine.md`.
- Cross-provider human identity resolution — Phase 04 (`phase-03-identity-continuity-doctrine.md`).

## Ownership boundary

Phase 03 owns **canonical projection contracts** and **deterministic derivation**. It must not bypass Phase 02 trust/evidence rules or Phase 01 raw truth.
